# راهنمای فارسی پروژهٔ شناسایی هویت با نگاه

**تهیه‌کننده:** Mobin Kheibary  
**استاد راهنما:** Dr. Shiva Kamkar

## این نسخه چه کاری انجام می‌دهد؟

این نسخه بررسی می‌کند آیا می‌توان هویت افرادِ از پیش شناخته‌شده را با استفاده
از حرکت چشم آن‌ها تشخیص داد، در حالی که وظایف ویدئویی مرحلهٔ آزمون کاملاً با
وظایف آموزش متفاوت هستند. بنابراین مسئله، «شناسایی بسته» (closed-set
identification) است: شناسهٔ افراد در آموزش و آزمون یکسان است، اما دادهٔ وظایف
آزمون هرگز در آموزش یا انتخاب مدل استفاده نمی‌شود.

این پروژه فقط نتایج همان داده‌های محلی را گزارش می‌کند. نتیجهٔ آن نباید به
معنای اعتبار بالینی، عملکرد برای همهٔ افراد، یا اثبات رابطهٔ علّی بین بار شناختی
و هویت نگاه تفسیر شود.

## نصب و اجرا

ابتدا در پوشهٔ `gaze_identity` قرار بگیرید. فایل‌های ویدئویی خام با پسوند
`.npz` باید در پوشهٔ هم‌سطح زیر باشند:

```text
../asreog_filter_order3_all_data/
```

سپس دستورهای زیر را اجرا کنید:

```bash
uv sync --extra dev
uv run python scripts/inspect_data.py
uv run python scripts/run_experiment.py
uv run pytest -q
```

دو فرمان اول به‌ترتیب کیفیت/ساختار داده و آزمایش اصلی را اجرا می‌کنند. فرمان
آخر آزمون‌های خودکار پروژه را اجرا می‌کند. تنظیمات تکرارپذیر در
`configs/baseline.json` قرار دارد.

## چگونه خروجی را بررسی کنیم؟

پس از اجرا، پوشهٔ `artifacts/task_disjoint_baseline/` شامل فایل‌های زیر است:

- `cohort_manifest.json`: جلسه‌های انتخاب‌شده، هش SHA-256 فایل‌های منبع و دلیل
  کنار گذاشتن جلسه‌ها؛
- `segment_exclusions.json`: قطعه‌های تصویری که به دلیل کیفیت داده وارد تحلیل
  نشده‌اند؛
- `predictions.csv`: پیش‌بینی هر قطعهٔ آزمون با شناسه و وظیفهٔ آن؛
- `results.json`: مدل انتخاب‌شده، معیارهای اعتبارسنجی و آزمون، ویژگی‌ها، و
  نسخهٔ محیط اجرا و هش پیاده‌سازی؛
- `run_metadata.json`: زمان اجرای متغیر که عمداً از نتیجهٔ قطعی جدا شده است.

برای مشاهدهٔ خواناتر نتیجه می‌توان از این دستور استفاده کرد:

```bash
uv run python -m json.tool artifacts/task_disjoint_baseline/results.json
```

## پروتکل پیش‌فرض

در پیکربندی فعلی، `task1` و `task2` برای آموزش، `task3` برای انتخاب مدل، و
`task7` و `task8` برای آزمون نهایی استفاده می‌شوند. کد، اشتراک هر وظیفه بین
آموزش، اعتبارسنجی و آزمون را خطا می‌داند. نام‌گذاری وظایف در فایل‌های محلی با
توضیح جداگانهٔ داده یکسان نیست؛ بنابراین تا پیش از تأیید منبع اصلی، در گزارش
از همین شناسه‌های محلی استفاده کنید و برچسب بار شناختی قطعی به آن‌ها ندهید.

## نکات مهم برای بررسی علمی

1. پیش از تغییر مدل، فایل manifest و تعداد افراد مشترک بین سه بخش را بررسی
   کنید.
2. فقط نتایج ذخیره‌شده در `results.json` را گزارش کنید؛ نتایج قدیمی معیار نهایی
   نیستند.
3. هر تغییر در وظایف، آستانهٔ کیفیت، ویژگی‌ها یا تعداد بازنمونه‌گیری باید در یک
   فایل پیکربندی جدید ذخیره و دوباره اجرا شود.
4. بازهٔ اطمینان bootstrap و مقدار p آزمون permutation به همان مجموعهٔ محلی و
   پروتکل دقیق وابسته‌اند و جایگزین تکرار مستقل پژوهش نیستند.

جزئیات سادهٔ پیاده‌سازی در [IMPLEMENTATION.md](IMPLEMENTATION.md) و گزارش
فارسی قابل تحویل در [REPORT_FA.md](REPORT_FA.md) آمده است.
